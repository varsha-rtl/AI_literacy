# Mission 3 - Understand the main ML approaches

## Comparison

| Approach | Training signal | Typical output | Example | Main limitation |
|---|---|---|---|---|
| Supervised learning | Input examples paired with target answers | Class, number, or other predicted target | Predict timing pass/fail from design-run features | Needs reliable labels that match the real decision |
| Unsupervised learning | Inputs without supplied target answers | Groups, low-dimensional representation, or unusualness score | Group similar design runs | A mathematically neat pattern may not be useful to an engineer |
| Reinforcement learning (RL) | Rewards and penalties received after actions | A policy for choosing actions | Choose placement actions that improve a PPA reward | Rewards can be hard to design, and exploration can be expensive or unsafe |
| Self-supervised learning | Targets constructed from the data itself, such as a hidden or next part | A representation or prediction model that can be adapted later | Predict a masked sequence element in a design log | The proxy task may not capture the downstream engineering goal |

Self-supervised learning is related to unsupervised learning because both can start without human labels. It is often separated because self-supervised training creates an explicit prediction target from each input, while unsupervised methods such as clustering directly search for structure. The labels are generated by a rule from the data, not supplied by an annotator.

## Simple process diagrams

### Supervised

```text
labelled examples (x, y)
          |
          v
   train model parameters
          |
          v
new input x ---> prediction y-hat ---> compare with y when a target is available
```

### Unsupervised

```text
unlabelled examples x
          |
          v
 find structure or compact representation
          |
          v
clusters / embedding / anomaly score
```

### Reinforcement learning

```text
state ---> agent chooses action ---> environment changes
  ^                                  |
  |                                  v
  +----------- next state <--- reward
```

### Self-supervised

```text
raw input ---> hide or transform part ---> predict the held-out part
    |                                      |
    +----------- repeat over many inputs -+
```

## When each is suitable

- Use **supervised learning** when the target is defined, examples can be labelled consistently, and a prediction will support a concrete decision.
- Use **unsupervised learning** when labels are unavailable and the first goal is exploration, segmentation, compression, or anomaly discovery.
- Use **reinforcement learning** when actions change a state and feedback can be expressed as a reward, such as searching a design space. Constraints and safe evaluation are essential.
- Use **self-supervised learning** when there is a large collection of raw data and a useful representation can be learned before a smaller labelled task. It is a pretraining strategy, not a guarantee of good downstream performance.

The learning approach and the task type answer different questions: the approach says how feedback is obtained, while the task says what output is wanted.
